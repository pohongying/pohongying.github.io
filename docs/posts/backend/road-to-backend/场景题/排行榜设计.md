# 排行榜设计

## 场景

通常是<u>游戏排行榜</u>，商品排行榜，视频排行榜，社交排行榜。

特点通常是实时变化，周期滚动

## 方案设计

1. 数据库排序。适用与数据量小
2. 数据库 + Redis。
3. 分布式系统。大数据这一套，kafka、hbase存储、spark排序计算
4. 基于NoSQL数据库。Mogodb
5. 最小堆 + Redis。展示固定长度，不实时

## Redis实现排行榜

### 幂等更新

主要是其他服务，在调用排行榜服务的时候，比如RPC调用，因为网络等一些问题，会出现请求重试，而造成分数重复增加，可以考虑增加一个`string` 类型的flag，用requestId作为全局Id，设计一个过期时间（不用太长）

### 同积分排名

有时候会出现积分相同的情况，我肯定希望先达到的排名越靠前，而不是id小的靠前，因此需要在`score` 的小数部分，作为时间戳，时间戳应该是由未来的一个时间，来减去现在的时间
