# 反射

***

### Java 动态代理核心知识总结

#### 一、是什么？(What is Java Proxy?)

Java 代理，从本质上讲，是一种**设计模式**。它允许我们为其他对象提供一个**代理**或**占位符**，以控制对这个对象的访问。客户端代码不直接与原始的“目标对象”（Target Object）交互，而是通过“代理对象”（Proxy Object）来间接交互。

这个代理对象看起来和目标对象一模一样（实现了相同的接口或继承了相同的类），但它可以在调用目标对象的真实方法**前后**，插入我们自定义的额外逻辑。

可以把它理解为一个“中介”或“经纪人”：

* **你 (客户端)**：想找明星（目标对象）办事。
* **经纪人 (代理对象)**：负责与你接洽。他会处理一些份外事（比如安排日程、过滤请求），然后再去联系明星本人。

代理主要分为两种：

1. **静态代理**：在编译期就需要手动为每个目标类编写一个代理类。实现简单，但如果接口增多或变更，需要维护大量代理类，非常繁琐。
2. **动态代理**：在程序运行时，通过反射等技术动态地创建代理类和对象。这是现代框架（如 Spring）的基石，也是我们讨论的重点。

#### 二、为什么？(Why Use Java Proxy?)

使用代理模式的核心目的，是为了遵循软件设计的**开闭原则（Open/Closed Principle）**：**对扩展开放，对修改关闭**。即在不修改目标对象源代码的情况下，为其扩展新的功能。

这带来了巨大的灵活性和可维护性，主要应用在以下场景：

1. **AOP（面向切面编程）**：这是代理模式最经典的应用。框架（如 Spring AOP）通过动态代理，将一些与核心业务无关但又普遍需要的功能（称为“切面”）动态地织入到业务代码中。
   * **统一日志记录**：在方法执行前后打印日志。
   * **事务管理**：在方法开始前开启事务，结束后根据执行结果提交或回滚。
   * **权限控制**：在方法执行前检查用户是否有权限。
2. **RPC（远程过程调用）**：当客户端调用一个远程服务时，框架会生成一个本地代理对象。客户端感觉就像在调用一个本地方法，但实际上代理对象在内部完成了网络通信、序列化和反序列化等复杂工作。
3. **懒加载（Lazy Loading）**：对于一个非常耗费资源的对象，可以先创建一个轻量级的代理对象。只有当客户端第一次真正调用它的方法时，代理对象再去初始化并加载那个沉重的真实对象。
4. **缓存**：代理可以在调用真实方法前，先检查缓存中是否有结果。如果有，则直接返回缓存结果，避免重复计算或查询，提升性能。

#### 三、怎么样？(How Does It Work?)

Java 中实现动态代理主要有两种主流方式：**JDK 动态代理** 和 **CGLIB 代理**。

| 特性 | JDK 动态代理 | CGLIB 代理 |
| :--- | :--- | :--- |
| **实现原理** | **实现接口**。在运行时动态创建一个实现了目标接口列表的新类。 | **继承父类**。在运行时动态创建一个目标类的子类。 |
| **核心要求** | **目标类必须实现至少一个接口**。 | 目标类**不能是 **`final`** 的**，否则无法被继承。 |
| **关键组件** | `java.lang.reflect.Proxy`<br>`java.lang.reflect.InvocationHandler` | `net.sf.cglib.proxy.Enhancer`<br>`net.sf.cglib.proxy.MethodInterceptor` |
| **方法限制** | 无特殊限制，只要是接口中定义的方法即可。 | **不能代理 **`final`** 方法**，因为子类无法重写 `final` 方法。 |
| **框架应用** | Spring AOP 在目标类实现接口且配置为非 `proxy-target-class` 时使用。 | **Spring Boot 2.x 及以后 AOP 默认使用**。应用更广泛。 |

#### 四、注意的点 (Key Points to Note)

1. **AOP 失效的常见场景**
   * **内部调用 (**`this`\*\* 调用)\*\*：在一个类的方法 A 中，通过 `this.方法B()` 来调用同类的另一个方法 B，此时对方法 B 的 AOP 增强会失效。因为 `this` 指向的是原始目标对象，而不是代理对象，调用绕过了代理。
   * **final 方法/类**：CGLIB 无法代理 `final` 方法或 `final` 类。
   * **private/static 方法**：AOP 无法增强 `private` 或 `static` 方法，因为它们不能被子类重写，也不属于接口定义的一部分。
   * **非 Spring Bean**：Spring AOP 只对由 Spring IoC 容器管理的 Bean 生效。一个通过 `new` 关键字手动创建的对象，不会被代理。
2. **Spring/Spring Boot 的默认选择**
   * 为了解决内部调用失效问题和统一代理行为，**Spring Boot 默认采用 CGLIB 代理** (`spring.aop.proxy-target-class=true`)。
   * 这意味着即使你的类实现了接口，默认情况下仍然会使用 CGLIB 创建基于子类的代理。
3. **性能差异可忽略**
   * 在现代 JVM 中，JDK 动态代理和 CGLIB 的性能差异已经非常小，通常不需要作为技术选型的关键考量。CGLIB 在创建代理对象时可能稍慢，但执行时稍快。
4. **理解注入的对象**
   * 在 Spring 中，当一个 Bean 被 AOP 增强后，从容器中获取（`@Autowired` 注入）的实际上是**代理对象**，而不是原始的目标对象。理解这一点对于调试和排查问题至关重要。
