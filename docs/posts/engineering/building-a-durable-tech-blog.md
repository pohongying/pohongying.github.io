# 如何搭建一个长期可维护的技术博客

一个长期可维护的技术博客，核心不是功能多，而是内容源稳定、发布链路简单、迁移成本低。

这个站点选择用 Markdown 作为唯一内容源，用 GitHub 仓库存储全部文章和项目说明，用 GitHub Actions 发布到 GitHub Pages。这样的好处是：写作、备份、版本管理和迁移都围绕 Git 完成，不依赖数据库或特定平台。

## 首版原则

- 内容优先，功能克制。
- 文章按主题组织，不被时间目录绑住。
- 首页承担个人品牌入口，文章区承担长期知识库。
- 先用 GitHub 网页编辑 Markdown，后续再按需要接入本地编辑器或 CMS。

## 后续可以增强什么

当文章变多后，可以继续补充自动生成文章索引、标签页、RSS、评论系统和访问统计。但这些都不应该阻碍首版上线。
